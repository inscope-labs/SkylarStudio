# tools/tsnet-android-bind

This directory is intentionally near-empty in source control. It exists as
the working directory for the `Phase 2 libtailscale Bind Spike` GitHub
Actions workflow (`.github/workflows/phase-2-libtailscale-bind.yml`) to run
`gomobile bind` against `tailscale.com/tsnet` in a real Go module context.

## Why the previous run failed

`gomobile bind` needs `golang.org/x/mobile` (specifically the `gobind` tool)
declared as a dependency in a `go.mod` — this repo is a Kotlin/Android
project with no `go.mod` anywhere, so the bare `gomobile bind ... tailscale.com/tsnet`
call in the old workflow had no module to resolve against and failed with:

```
gomobile bind requires golang.org/x/mobile in the current module, but it is
not in the module dependency graph.
```

## Why `go.mod` / `go.sum` aren't committed here

They're generated fresh by the CI job itself (`go mod init`, `go get
golang.org/x/mobile/cmd/gobind`, `go get tailscale.com/tsnet`) rather than
hand-written and committed. (`go get -tool ...` was tried first per
gomobile's own suggested-fix text, but `-tool` is Go 1.24+ only and this
workflow pins Go 1.23.0 — a plain `go get` works on any Go version and
satisfies the same "in the module dependency graph" requirement.) This
sandbox has no network path to the Go
module proxy to produce a real, checksummed `go.sum` — committing one typed
by hand would be an unverifiable stand-in, not an actual pinned dependency
graph. CI has real network access, so it resolves the real thing every run.

**Follow-up once Phase 2 reaches a go/no-go decision:** if "go" is the
verdict, commit a real `go.mod`/`go.sum` here (generated by an actual `go`
toolchain with real network access, e.g. locally or in a one-off CI step)
so the binding version is pinned and reproducible instead of re-resolving
`@latest`/newest-compatible on every run.

## Why binding `tailscale.com/tsnet` directly also failed

Getting past the module-bootstrap issue above surfaced a second, unrelated
problem: `gobind` requires every bound function/method to return at most
one non-error value, and `gomobile bind` binds a package's *entire*
exported surface. `tsnet.Server.Loopback()` returns four values, so
binding `tailscale.com/tsnet` directly can never work regardless of which
methods are actually needed.

Fixed by adding `tsnetbind/` — a small wrapper package with a
gobind-compatible surface (`New`, `Start`, `Stop`) that calls into `tsnet`
internally. The workflow now binds `./tsnetbind`, not `tailscale.com/tsnet`
directly. See `tsnetbind/tsnetbind.go`'s doc comment for what's wrapped,
what's deliberately not, and its verification status (written from general
API knowledge, not yet compiled anywhere — CI is the first real check).
